# Виртуальный РОП — инфраструктура и решения

## Как подключиться (читать первым делом)

В приложении Claude настроен MCP-сервер **`ropbot`** — прямой доступ к серверу проекта из любой
сессии. Инструменты: `ssh_run`, `sql`, `write_file`. Если их не видно — `RefreshMcpTools`, затем
`ToolSearch` по `ropbot`. Файл моста: `/Users/timofey/ropbot-mcp/server.py` (запуск через `uv`),
ключ `/Users/timofey/.ssh/ropbot`.

Ещё MCP на маке: `yandex_metrika` и `yandex_direct` — `/Users/timofey/.local/share/yandex-mcp/`,
токены в `~/.config/yandex-mcp/.env` (Claude туда не пускают — просить Тимофея). Те же токены
продублированы в `.env` сервера (`YANDEX_METRIKA_TOKEN`, `YANDEX_DIRECT_TOKEN`) — серверные
скрипты ходят в API сами, без мака.

**Память проекта — этот каталог `/opt/ropbot/memory/` плюс база на сервере.**
Выводы перепроверяются запросом, а не памятью.

Ограничения MCP-моста: команды режутся по таймауту 60 секунд; долгое — в фон с выводом в файл.
Осторожно: `timeout N docker compose run …` убивает клиент, а контейнер живёт — проверять
`docker ps | grep run` и удалять зависшие.

## Результаты первого аудита (90 дней, август 2026)

25 тыс. звонков, 104 тыс. лидов, 1 160 сделок. **Воронка живёт в статусах лидов, не в сделках.**
Цикл сделки: медиана 8,6 дня, 90-й процентиль 38 дней.

- **Две трети лидов приходят, когда офис закрыт.** Медиана первого звонка у них 960 минут против 67, конверсия 0,67% против 1,40%
- **Нет настойчивости.** 63% лидов получают 0–1 звонок. «Недозвон» — 31,9% базы. Конверсия растёт: 1 звонок 0,50% → 4–5 звонков 2,51% → 10+ 8,77%
- **383 «недозвона» без единого исходящего**, 94% у двух менеджеров (М6 Николай, М7 Дмитрий)
- **Статусы недостоверны.** Спам от 7,8% до 41,9% при одинаковом потоке
- **Повторное обращение — сильнейший сигнал:** 3–4 обращения дают 5,31% против 1,05%
- **8% заявок с непригодным номером**, сделок среди них ноль
- **Июль:** поток +30%, сделок 47 против 52 в июне. Наращивать рекламу нельзя
- Суммы проставлены в 72 из 1 024 успешных сделок, средний чек 349 тыс. ₽

**Восстановимая база: 6 050 лидов** с живым номером, закрытых отказом после 0–1 звонка,
из них 2 181 не набирали ни разу.

## Скоринг заявок (работает с 19–20.08.2026)

Подробно — `lead-scoring.md` в этом же каталоге. Коротко: боевая модель **v2b** оценивает шанс
продажи **только по поведению клиента на сайте** (Метрика по ClientID) до первого звонка;
классы A/B/C/D + балл 0–100. Конверсия классов на истории: A 3,59%, B 2,05%, C 0,80%, D 0,31%.
CRM-модель `v1` работает в тени для сравнения.

**Вывод — не в телеграм, а в CRM** (решение Тимофея 20.08): `marker.py` пишет класс в поле
«Категория клиента» (`UF_CRM_1787201112`) всем лидам с 1 августа, класс A получает «⚡»,
класс B — «★» первым символом названия. Сопоставленные по времени идут с меткой «≈».
Телеграм-дайджест выключен из крона (`digest.py` остался для ручного запуска).

Cron на хосте (MSK): `enrich --days 2 && score` */5 мин; `marker.py` */10 мин;
`metrika.py match` */30 мин; ночной enrich истории 22:00; `train --model all` 01:10.
Логи в `/var/log/ropbot/`. Замер точности стартовал 20.08, сверка 2 сентября.
