# Скоринг заявок — кому звонить первым

19.08.2026 запущен; тем же вечером пивот по решению Тимофея: ранжирование **только по
поведению из Метрики/Директа** (CRM-статусы недостоверны). Боевая модель `v2b`, CRM-модель
`v1` — теневая, для сравнения. 20.08 второй поворот: **вместо телеграм-рассылки — маркировка
прямо в Битриксе**, телеграм-дайджест выключен из крона.

## Маркировка в Битриксе (с 20.08, лиды с 1 августа и новые)

`marker.py`, каждые 10 минут, поле **«Категория клиента»** (`UF_CRM_1787201112`, string):

- **A/B/C/D** — v2b по точному ClientID
- **A≈/B≈/C≈/D≈** — клиент найден сопоставлением по времени (см. ниже), доверие ниже
- **нет данных** — в Метрике не виден и однозначно не сопоставлен
- **номер непригоден** — мусорный телефон

Значок первым символом названия лида: **A → «⚡», B → «★»** (только точные классы, «≈» без
значка). При смене класса значок заменяется, при потере класса — снимается.

Журнал — `lead_marks`; оригиналы названий до правки — `lead_title_backup` (страховка отката).

⚠️ **Грабля: Битрикс обрезает TITLE до пустоты на 4-байтовых эмодзи (🔥 и подобных).**
Первые 17 заявок потеряли названия — восстановлены. Проверены и работают: ⚡ ★ ◆ ✔ ❗ (BMP).

## Сопоставление по времени (для заявок без ClientID)

`metrika.py match` (каждые 30 мин): окно [T−30 мин; T+3 мин], точное совпадение UTM-кампании
и города (если есть у обеих сторон), для Venyoo — обязательная цель «Venoo» (354790295);
матч засчитывается **только при единственном кандидате**. Валидация на 400 лидах с известным
ответом: мягкие ключи — точность 12,5% (отброшено), строгие — **65,7%**. Поэтому метка «≈»
и отдельная группа в замере. `match_kind` в `lead_visits`: `exact` / `time` / `time_none`.

## Замер точности — старт 20.08

Оценки замораживаются при выставлении (`lead_scores`, PK lead_id+model). Сверка прогноза с
фактом: **2 сентября** (напоминание стоит), зрелая — конец сентября (p90 цикла 38 дней).

## Боевая модель v2b — только поведение

Признаки из `lead_visits` на момент заявки: визиты (1/2–3/4+), дни с первого визита
(0/1–7/8+), страницы (1–2/3–10/11–30/31+), время (<1/1–10/10+ мин), лоты, тип источника,
кампания Директа визита, устройство, **страницы доверия** (с 21.08). Наивный Байес, WOE, k=250, MIN_N=60, shrink 0.75,
перцентильная калибровка; целевая — `status_semantic='S'`. Ночной train 01:10 МСК
(20.08: 3 352 лида, 47 продаж).

**Страницы доверия (добавлено 21.08.2026).** Заходил ли клиент до заявки на
`/about`, `/reviews`, `/how-buy`, `/contacts`, `/delivery`, `/favourites`,
`/autosender-otzyvy` (константа `TRUST_RX` в `scorer.py`). На истории: **3,49% против
1,16%** — сильнейший положительный вес модели (0,71). Проверено на подмену причиной:
эффект держится внутри каждой группы по глубине просмотра (до 10 страниц 0,66% → 4,48%;
11–30 стр. 1,32% → 2,56%; 31+ стр. 2,44% → 3,61%), то есть это не следствие того,
что человек просто много листал.

Прирост от признака измерен на одной выборке (6 719 лидов, 86 продаж): класс A
2,85% → **3,08%**. Прирост скромный, потому что признак редкий — 344 лида из 6 719 (5%):
он сильно двигает конкретные заявки, но мало влияет на общую статистику.

Разделы каталога в скоринг **не берём**: Япония 1,34%, Корея 1,29%, Китай 1,16% —
все около базы. Отвергнуты также число просмотренных марок (немонотонно: 1 марка хуже,
чем 0 или 2–3 — шум), статьи (0,84%), калькулятор растаможки и мотоциклы (ноль продаж
при мизерном объёме).

Яркие веса: «вернулся в течение недели» 2,57%; «30+ страниц» 2,39% против «1–2 страницы»
0,29%; **«смотрел лоты» — ХУЖЕ** (1,12% vs 1,61%); поиск 0,90% хуже рекламы 1,36%;
кампания tk_708545020 худшая и по поведению (0,45%) — кандидат на отключение.

## Ревизия 22.08.2026 (полный аудит цепочки)

Проверено и **в порядке**: заморозка оценок цела (0 расхождений между `lead_scores` и
маркировкой в CRM); веса монотонны и осмысленны; квота Метрики отпустила (12 410 профилей,
три 429 за сутки); дыра расписания оказалась почти пустой (4 лида).

Найдено и **исправлено**:

1. **Недосчитанная сессия (train/serve skew).** Прод обогащал лид через ~5 минут после
   заявки — сессия клиента ещё шла, страницы/секунды фиксировались обрубком, а обучение
   видело те же сессии целиком (тянуло их спустя дни). Свежие заявки систематически
   занижались и замораживались заниженными. Лечение: `enrich` берёт лиды только старше
   45 минут (сессия закрывается через 30 минут тишины).
2. **Двойная запись в Битрикс.** Свежий лид получал «нет данных», а через час — класс.
   Теперь `marker` держит лиды с ClientID 75 минут до прихода поведения и пишет один раз.
3. **Зависшие без обогащения.** Крон `enrich` смотрел только 2 дня назад, ночной — только
   старше 45 дней: лид, пропустивший обогащение из-за квоты, в окне 2–45 дней не
   ретраился никогда. Окно крона расширено до 45 дней (`NOT EXISTS` делает это бесплатным).

**Честная оговорка, вписана в модель мира:** «страницы» во всех поведенческих признаках —
это страницы **входа** в визиты (stat API отдаёт только `startURLPath`). «Смотрел лоты» =
«заходил с лота» (глубокие ссылки рекламы/закладки), «страницы доверия» = «визит начинался
с отзывов/о компании/избранного». Измеренные конверсии верны для признаков как они
определены, но полные маршруты внутри сессий доступны только через Logs API —
кандидат в улучшения, если решим копать глубже.

Также замечено: `marker.py` теперь общий с механикой короны ♛ (составная оценка,
`composite.py`, ведётся в другом чате) — правки согласованы, корона не тронута.
