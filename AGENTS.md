# AGENTS.md — Виртуальный РОП (/opt/ropbot)

Файл читают все AI-агенты (Claude, Codex и следующие). Правила общие для всех.

Контекст проекта, решения и история — в реестре `/opt/knowledge`
(репозиторий `autosender-knowledge`). **Читать его перед работой**, правила — в его `rules.md`.
Здесь только то, что касается этого кода.

## Что это

Сервер 5.35.99.93, каталог `/opt/ropbot`. Скоринг заявок, синхронизация с Битрикс24,
расшифровка звонков, QA-оценка разговоров, панели менеджеров, Telegram-бот `@ironbossAS_bot`.
Шесть контейнеров, боевой Postgres с реальными лидами и сделками.

## Главное: это ПРОД, тестового контура нет

Решение принято сознательно (13.09.2026): отдельный тест не поднимаем, правим наживую.
Отсюда всё остальное.

- **Рабочая копия одна — эта.** Клонов ни у кого нет, деплоя нет, `git pull` на сервер нет.
- **Claude** работает здесь напрямую. **Codex** — через MCP `ropbot` (`ssh_run`, `write_file`,
  `sql`), то есть в этом же каталоге. Локальный клон на маке — только для чтения кода.
- **Веток нет. Только `main`, прямой коммит.** Ветка переключила бы файлы под руками
  у второго агента и под работающими контейнерами.

## Порядок работы

1. `git status`. **Дерево грязное = кто-то уже внутри.** Остановиться и спросить Тимофея,
   не править поверх.
2. Коммит перед началом, если что-то висит незакоммиченным.
3. Правка.
4. Применить изменение (см. ниже — способ зависит от каталога).
5. Проверить, что сервис жив: `docker ps`, логи.
6. Коммит сразу, пока помним что и зачем. Затем `git push`.
7. Запись в `/opt/knowledge/changelog.md` по правилу 3 реестра.

## Как изменение доезжает до работы — по каталогам

| Каталог | Как исполняется | Что сделать после правки |
|---|---|---|
| `app/` | **запечён в образ** (`build: ./app`), тома с кодом нет | `docker compose build && docker compose up -d`, либо `./rebuild_now.sh` для ASR. **Без пересборки правка не действует** |
| `web/` | запускается с хоста (`build.sh`, `docker exec ... < web/visual_daily.py`) | действует сразу, пересборка не нужна |
| `lab/` | скрипты с хоста | действует сразу |
| `tools/`, `bin/`, `cron/` | хост, крон | действует сразу; после правки `*.cron` проверить `systemctl list-timers \| grep cron-` |
| `db/*.sql` | применяется вручную | см. раздел про базу |

## База данных

Боевая. В ней настоящие заявки, сделки и разговоры менеджеров.

- Перед любым изменением схемы или данных — дамп затронутых таблиц (`pg_dump -t`).
- Никаких `DELETE` и `UPDATE` без `WHERE`. Перед ними — `SELECT count(*)` с тем же условием.
- Чтение — свободно. Postgres слушает только `127.0.0.1:5432`, наружу не торчит.

## Ручные бэкапы файлов запрещены

До 13.09.2026 правки страховались копиями: накопилось 72 файла `.bak`, из них
**43 копии одного `dash.py`**. Всё перенесено в `backups/manual-bak-2026-09-13/`.

Теперь для этого есть git. `*.bak` закрыт в `.gitignore`.

Осторожно: скрипты `web/patch_*.py` до сих пор делают `shutil.copy(P, P + ".bak-…")`.
Это наследие. Запускать их не нужно, правку делать прямо в файле и коммитить.
В `dash.py:6183` есть комментарий со ссылкой на `dash.py.bak-nowon` — он теперь в архиве.
