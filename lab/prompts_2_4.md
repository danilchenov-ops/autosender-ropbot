# Промты 2–4 пайплайна «Эталонный скрипт»

Постановка Тимофея, 21.08.2026. Промт 1 лежит в `prompts.py` (там же описано,
почему добавлено поле `roles`). Промты 2–4 исполняются не через ProxyAPI,
а в сессии Claude: это по одному большому аналитическому вызову на шаг,
где качество рассуждения важнее цены токена.

Отличие от исходной постановки одно и оно принципиальное: **частоты считает
`aggregate.py`, а не модель**. Промт 2 требует «ЧАСТОТЫ, НЕ ВПЕЧАТЛЕНИЯ» —
надёжнее посчитать их кодом по карточкам и отдать модели готовую таблицу,
чем просить модель считать по 1272 карточкам и надеяться на арифметику.
Модель получает: посчитанные метрики, разбивку по стратам, проверенные
цитаты и сырые карточки-примеры. Её работа — интерпретация и отбор.

## Промт 2. Сравнение групп → паттерны

```
Ты — аналитик продаж. У тебя есть формализованные карточки разговоров, размеченные по итогу в CRM:
WON — сделка закрыта успешно, LOST — нет.

КАРТОЧКИ WON ({{N_WON}} шт.):
{{JSON_WON}}

КАРТОЧКИ LOST ({{N_LOST}} шт.):
{{JSON_LOST}}

Найди, что СИСТЕМАТИЧЕСКИ отличает WON от LOST. Работай по правилам:

1. ЧАСТОТЫ, НЕ ВПЕЧАТЛЕНИЯ. Каждое утверждение подкрепляй счётом в формате
   «X из {{N_WON}} WON против Y из {{N_LOST}} LOST». Без счёта утверждение не выводи.
2. ТОЛЬКО УПРАВЛЯЕМОЕ. Отличие должно быть действием менеджера, которое он может повторить
   в следующем разговоре. «Клиент был заинтересован», «крупная компания» — не годятся.
3. ПРОВЕРЬ КОНФАУНДЕРЫ. Прежде чем объявить паттерн, посмотри метаданные (источник лида, сегмент,
   сумма, менеджер, длительность). Если отличие объясняется тем, что WON-звонки шли из другого
   источника / к другому сегменту / от одного сильного менеджера — так и напиши, и пометь паттерн
   как СПОРНЫЙ. Не выдавай качество лида за качество скрипта.
4. ОБРАТНАЯ ПРОВЕРКА. Для каждого паттерна найди контрпримеры: WON без него и LOST с ним.
   Укажи их количество. Если контрпримеров много — понижай уверенность.
5. ЧЕСТНОСТЬ О ВЫБОРКЕ. Если паттерн опирается на менее чем 5 наблюдений — помечай ГИПОТЕЗА,
   а не вывод. Если данных не хватает вообще — скажи прямо, не заполняй пустоту здравым смыслом.
6. ЦИТАТЫ РЕАЛЬНЫЕ. Все формулировки бери дословно из карточек. Ничего не переписывай «покрасивее».

Выведи в Markdown:

## A. Сводная статистика по группам
Таблица: метрика | WON (среднее/доля) | LOST | разрыв.
Метрики: доля речи менеджера, число открытых вопросов, доля разговоров с выясненным бюджетом,
доля с выявленным ЛПР, момент называния цены, доля с конкретным следующим шагом с датой, и т.д.

## B. Подтверждённые отличия (уверенность высокая)
Для каждого: что делает менеджер → счёт WON vs LOST → 2–3 дословные цитаты из WON →
контрпримеры → почему это работает.

## C. Спорные отличия (возможен конфаундер)
Что именно может объяснять отличие помимо действий менеджера.

## D. Гипотезы (мало данных)
Что стоит проверить, собрав больше разговоров.

## E. Антипаттерны LOST
Действия/фразы, встречающиеся в LOST существенно чаще. С цитатами и счётом.
Отдельно: на каком этапе чаще всего срывается разговор и по какому маркеру это видно заранее.

## F. Чего в данных нет
Какие вопросы нельзя закрыть этой выборкой.
```

## Промт 3. Сборка эталонного скрипта

```
Ты — руководитель отдела продаж. На основе анализа ниже собери ЭТАЛОННЫЙ СКРИПТ —
такой, на который менеджеры равняются в работе.

АНАЛИЗ:
{{ВЫВОД_ПРОМТА_2}}

БАНК ЦИТАТ ИЗ УСПЕШНЫХ РАЗГОВОРОВ:
{{ЦИТАТЫ}}

КОНТЕКСТ КОМПАНИИ:
Продукт: {{ПРОДУКТ}}
Целевой клиент: {{ЦА}}
Цена/вилка: {{ЦЕНА}}
Канал: {{ЗВОНОК/ПЕРЕПИСКА}}
Целевое действие звонка: {{НАПРИМЕР: назначенная встреча / выставленный счёт}}

ЖЁСТКИЕ ПРАВИЛА:
- Каждый речевой модуль — либо дословная фраза из WON-разговора, либо её минимальная адаптация.
  Рядом с каждым модулем ставь пометку [из WON #ID] или [адаптация #ID] или [НЕТ В ДАННЫХ].
- Модули с пометкой [НЕТ В ДАННЫХ] используй только там, где без них скрипт разваливается,
  и собери их в конце в отдельный список «требует проверки на практике».
- Опирайся на раздел B. Из C и D бери только с явной пометкой «гипотеза, тестировать».
- Скрипт должен быть произносимым вслух: короткие предложения, живой язык, без канцелярита
  и без маркетинговых штампов, которых нет в реальных разговорах.
- Не пиши «установите контакт» — пиши, что именно сказать.

СТРУКТУРА ВЫВОДА:

# Эталонный скрипт: {{НАЗВАНИЕ}}

## Цель разговора и критерий успеха
## Карта разговора
## Этап 1..N
   Цель этапа / Что говорим / Что должны узнать / Переход дальше /
   Красные флаги / Чего не делать
## Блок отработки возражений
## Закрытие
## Чек-лист самопроверки менеджера (10–15 пунктов)
## Карточка оценки разговора (сумма 100, веса по силе разрыва WON/LOST)
## Требует проверки на практике
```

## Промт 4. Валидация скрипта

Контрольная выборка отложена ДО прогона промтов 1–3: `lab_sample.split='holdout'`,
25 % клиентов, отбор по хешу номера телефона — не по дате и не вручную,
чтобы нельзя было подкрутить.

```
Ты — скептик-проверяющий. Тебе дан скрипт, выведенный из одной выборки разговоров,
и КОНТРОЛЬНАЯ выборка разговоров, которую при построении скрипта не использовали.

СКРИПТ:
{{СКРИПТ}}

КОНТРОЛЬНАЯ ВЫБОРКА (с метками WON/LOST):
{{ДИАЛОГИ}}

Сделай:
1. Оцени каждый контрольный разговор по «Карточке оценки» из скрипта. Выведи таблицу:
   dialog_id | балл | фактический итог.
2. Посчитай, разделяет ли балл группы: средний балл WON против LOST, есть ли пересечение.
   Если разделения нет — скажи прямо, что скрипт не подтверждён.
3. Найди WON с низким баллом. Что менеджер сделал вместо скрипта и почему это сработало?
   Значит ли это, что в скрипте не хватает ветки?
4. Найди LOST с высоким баллом. Значит ли это, что критерий переоценён или что дело не в скрипте?
5. Назови критерии с нулевой различающей силой — их из карточки оценки надо убрать.
6. Выдай конкретный список правок скрипта. Только те, что следуют из контрольной выборки.
```
